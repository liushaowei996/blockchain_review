# Coding decisions for the expanded OAL synthesis

The unit is a scoped mechanism claim. These decisions document a source-checked extraction and sensitivity analysis, not independent duplicate coding or agreement between coders. Study IDs refer to `oal-study-register.csv`; supporting passages are in each claim record. Counts describe reported mechanisms and evidence forms, not independently verified security guarantees.

1. **Application domain and evaluation setting are separate.** The direct-domain stratum contains 11 UAV studies (S01–S04, S20–S21, S24–S25, S30–S31, S39), three maritime AIS studies (S27–S29), and five intended underwater studies (S05–S06, S32–S34). Twenty transferable studies form a separate stratum. S20 and S21 explicitly target UAV GNSS protection and belong to the direct-domain stratum even though their evaluation uses models/data. This classification does not imply physical deployment.
2. **Authenticating a sender differs from corroborating a report.** S25 describes public-key registration and signatures, but evaluates cooperation in NetLogo. Its C claims receive L0, while simulated report corroboration and partner appraisal receive L2. The paper's blockchain-inspired design is not automatically assigned a G claim. S39 explicitly records trust offsets through simulated blockchain modules, so its G claim receives L2.
3. **Recorded observations are not a new operating trial.** S24 uses a real photogrammetry trajectory with constructed spoofing cases. It supports D/O at sensing and fusion with L2. Its discussion identifies texture and illumination limitations; visual odometry is not assumed to transfer unchanged to open water or darkness. S22 likewise remains L2 for recorded GNSS validation.
4. **Receiver provenance is not original AIS-source authenticity.** S27 signs submissions from authorized monitoring receivers and retains them in Fabric. This supports membership, record binding and shared history. It does not demonstrate that an unauthenticated original AIS sender reported a true position. The inspected deployment specifies Raft; broad security prose is not treated as a Byzantine-ordering result.
5. **L3 does not rank cryptographic strength.** S28's pAIS software demonstrates protected-message formatting and processing using 256-bit RSA and an 8-bit checksum. These demonstration parameters do not establish deployment-grade protection. S29 implements SecAIS authentication and key-distribution modes in Java with simulated AIS encoders/decoders. Architectural modes that were not implemented are not silently assigned the prototype's evidence profile.
6. **Positive continuity mechanisms are retained.** S30 and S39 update trust and specify exclusion/revocation. S31 couples changing reputation with path selection. They are precedents for reassessment, not merely admission mechanisms. Their evidence does not establish all of event-time authority reconciliation, downstream-product invalidation and integrated air–surface–underwater operation.
7. **S31 contains two evaluation settings.** The publisher describes eight physical UAV nodes, onboard computers/radios, timed black-hole behavior and a link interruption. L3/L4 is assigned only to cooperation/path adaptation. Consensus benchmarking uses a separate container platform. The described leave/revocation contracts receive L0 where an isolated recovery evaluation is not reported. L4 denotes the bounded physical-node experiment; no specified weather envelope, sustained coalition governance or complete maritime mission is inferred. A conservative L3-only variant is released.
8. **Underwater naming is not underwater validation.** S32 reports security reasoning and desktop C timings; acoustic-channel operation and environmental-noise key entropy are not measured in that benchmark. S33 uses MATLAB network simulation; its 6G application label does not demonstrate a physical 6G underwater link. S34's detailed evaluation uses UNSW-NB15 terrestrial intrusion data despite its underwater framing. It remains a proxy experiment and is removed in a direct-domain sensitivity variant.
9. **Task suitability is scoped to the task.** S26 appraises fog partner history and processor/queue capacity for offloading. It supports E/M and P/M at processing, not observation truth or confidential computation. S34's filtering concerns participants and model updates at aggregation, not sensor calibration. Neither is converted into a mission-wide trust score.
10. **Shared cells preserve different fault assumptions.** S35–S38 are separately identifiable generic consensus comparators. Raft's crash model and PBFT/HotStuff/Tusk's Byzantine models are retained in scope notes. A shared D/G/F cell does not make these protocols substitutes. Removing all four comparators tests whether the map's main concentration is produced by their inclusion.
11. **Evidence does not spread from one protocol path to another.** The original PBFT paper explicitly states that its prototype did not implement view changes or retransmissions. S38 therefore has L1/L3 for normal replicated operation and L1 for recovery. Raft's failover experiment supports L3 for recovery; its configuration-change argument is coded L1. A paper-wide prototype label would erase these differences.
12. **Alternative object assignments and single-study dependence are visible.** The E/P distinction for S01–S03 admission identities is tested by moving those P/C/A rows to E/C/A. All 39 leave-one-out maps are released. Layer co-occurrence counts identify papers discussing both layers; they do not establish a validated handover. Zero counts remain separate from mission-specific applicability decisions.

The sensitivity outputs are descriptive. They measure how inclusion and coding choices affect this map, and do not estimate field prevalence, establish OAL's predictive accuracy, or replace a controlled comparison of design-review methods.
